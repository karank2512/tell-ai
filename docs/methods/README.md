## Backtest reports (spec section 13)

`tell backtest <name> [--as-of DATE] [--out DIR] [--refresh]` writes `<name>-<YYYY-MM-DD>.md` and a full copy as `<name>-latest.md` (only when no newer dated report is already in the directory, so a regenerated past date never moves the pointer back; the dated file is the citable source). `tell backtest refresh` (also spelled `tell backtest --refresh`) writes every public report. The weekly workflow runs it with `--out tell-data/site/methods` and commits the reports to [tell-data](https://github.com/karank2512/tell-data/tree/main/site/methods), never here (ADR 0025); the index below lists only reports a maintainer regenerated by hand into this directory. The per-command `--refresh` flag means something narrower: fetch external inputs missing from the cache. Only `velocity-lead --refresh` fetches anything (Wayback CDX listings into `tell-private/cache/wayback`), and the weekly workflow never passes it and has no `tell-private` checkout, so the Wayback reconstruction in 13.2 is fetched only by a maintainer running `tell backtest velocity-lead --refresh` locally; `weekly.yml` reads the cache only and reports unfetched boards as such. Templates: `docs/methods/templates/`. Each report states the question, the cohort, N, the query or script, the numbers, the caveats and the date. A number with N under 30 is printed as "(N=12; too small to quote)" and the report's front matter then says `quotable: false`; launch drafts and resume lines quote only `quotable: true` reports.

### Manual interventions and "weeks unattended"

SPEC 13.4 defines "weeks unattended" as days since the last manual intervention needed to
keep ingest green, from the `runs` table, divided by 7. The `runs` table cannot see a
human, so an intervention is a run that carries the marker `runs.notes.manual = true`,
written by the run lifecycle (`tell/collectors/base.py`) on every run recorded while the
marker is on:

- `TELL_RUN_MANUAL=true` in the environment. `ingest.yml` sets it to
  `${{ github.event_name == 'workflow_dispatch' }}`, so a run dispatched by hand from the
  Actions page or `gh workflow run ingest.yml -f source=...` (the way one collector is
  re-run after a fix) marks every run it records, and a scheduled run never does.
- The global CLI flag `tell --manual <command>` (for example
  `tell --manual ingest --source lever --force` after a hotfix from a terminal), which
  wins over the variable for that invocation.

`tell backtest ops` anchors the unattended period on the latest marked run (its
`finished_at`); with no marked run it counts from the first run ever and the report says
so. `tell runlog --week` prints a proxy beside it, the weeks since the last gap of more
than 24 hours without a successful scheduled run, as a cross-check for fixes nobody marked.
Runs of the nightly intake reader (`source = intake`, which runs in `tell-private`) are not
pipeline runs: they count toward neither the success rate nor the anchor. Rule for the
operator and rationale: ADR 0028; deployment side: `docs/deploy/github-actions.md`,
"Re-running one source".
