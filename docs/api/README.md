# Static API v0

The v0 API is static JSON on GitHub Pages, regenerated by every ingest run (four times a
day) and validated against its schema before it is pushed. There is no server, no key and
no rate limit beyond GitHub Pages' own; responses are cached for about 10 minutes.
Spec: `docs/SPEC.md` sections 9 and 10. Code: `tell/publish/json_api.py`.

Base URL: `https://karank2512.github.io/tell-data` (`TELL_BASE_URL`).

| Call | Returns | Schema |
| --- | --- | --- |
| `GET /api/v0/companies/{domain}.json` | The per-domain object below | [`company.schema.json`](company.schema.json) |
| `GET /api/v0/weekly/latest.json` | The current weekly edition's top lists and coverage | `WEEKLY_SCHEMA` in `tell/publish/json_api.py` |
| `GET /api/v0/watchlists/{slug}.json` | A public watchlist: its companies, highest score first, each with `heat` | `WATCHLIST_SCHEMA` (each company: `company.schema.json`) |
| `GET /api/v0/health.json` | Run-health per source | `HEALTH_SCHEMA` |

A domain with no file is either unknown to tell or has had no signal for 180 days (the
size budget, see `docs/methods/publishing.md`); both mean "nothing to report".

## The per-domain object

```json
{
  "domain": "acme.com", "name": "Acme", "as_of": "2026-10-06",
  "profile": "default", "score": 9.4,
  "contributions": [
    {"type": "funding", "contribution": 5.9, "occurred_at": "2026-09-29",
     "summary": "Form D: $18,000,000 offering, $18,000,000 sold",
     "url": "https://www.sec.gov/Archives/edgar/data/.../"},
    {"type": "hiring_velocity", "role_family": "sales", "contribution": 3.5,
     "occurred_at": "2026-10-03", "summary": "4 new sales roles in 7 days vs 0.5 baseline",
     "url": "https://boards.greenhouse.io/acme",
     "postings": [{"title": "Account Executive, Mid-Market", "posted_at": "2026-10-01", "url": "..."}]}
  ],
  "open_postings": 23, "long_open_roles": 2,
  "sources": {"ats": "greenhouse:acme", "edgar_cik": "0001234567", "news": true},
  "generated_by": "https://github.com/karank2512/tell-ai/commit/<sha>",
  "why_not_higher": [
    {"type": "launch", "decayed_at": "2026-09-26", "url": "...", "summary": "..."}
  ]
}
```

| Key | Meaning |
| --- | --- |
| `score` | Raw sum of decayed contributions (spec section 8), one decimal. |
| `heat` | 0-100 percentile of the score within a watchlist. Present only inside `api/v0/watchlists/{slug}.json`. |
| `contributions[]` | One per signal with a positive decayed contribution, largest first. Values are rounded to one decimal so that they add up to `score` exactly. Every entry has a receipt `url`. |
| `contributions[].postings` | For `hiring_velocity`: the counted postings (title, posted date, URL). |
| `open_postings` | Open postings on the company's job boards. |
| `long_open_roles` | Open postings older than 90 days (weighted 0.25; over 180 days, 0). |
| `sources.ats` | `vendor:identifier` of the active board, or `no_board` (including unsupported vendors such as Workday). |
| `sources.edgar_cik` | 10-digit SEC CIK when the company is linked to EDGAR, else `null`. |
| `sources.news` | A company feed or a news event is known. |
| `generated_by` | The code commit that produced the file (`local` for a local build). |
| `why_not_higher[]` | Signals whose contribution decayed to zero in the last 30 days (extension to the spec example). |

Conventions: dates are ISO 8601 calendar dates (`YYYY-MM-DD`, UTC); wherever an amount
appears (weekly `top_funding[].amount_usd`) it is an integer number of US dollars, `null`
when undisclosed; no field ever holds a person's name, email or phone.

## Clay recipe (spec section 10)

1. Add an **HTTP API** enrichment column.
2. Method `GET`, URL `https://karank2512.github.io/tell-data/api/v0/companies/{{domain}}.json`,
   no authentication, no headers.
3. Map output columns: `score`, `contributions[0].summary`, `contributions[0].url` (and
   `sources.ats` to see coverage at a glance).
4. A 404 means no signal in the last 180 days, or a domain tell does not watch yet: ask for
   it through the "Watch these domains" issue form or the intake form.

GitHub Pages sends CORS-friendly static responses and caches for 10 minutes, which is fine
for data that changes four times a day.
